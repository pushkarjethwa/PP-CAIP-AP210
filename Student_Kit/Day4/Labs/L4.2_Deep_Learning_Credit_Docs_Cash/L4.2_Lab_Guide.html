Objective & scenario alignment

Horizon Gulf Bank (HGB) is a fictional UAE retail bank with 250,000 customers. Its Board approved Project MIZAN — an AI decisioning platform covering credit, fraud, collateral valuation, cash logistics, customer retention and document automation. You are a junior ML practitioner in the MIZAN squad.

Part A — Credit: Model Risk wants a neural challenger to the L3.1 logistic PD model. Part B — Operations: 15,000 scanned onboarding documents a month are routed by hand; a CNN could route them automatically. Part C — Treasury: can an LSTM beat the classical forecasting baselines for next-day network cash demand?

Progressive architecture: benchmarks come from L3.1 and L2.2; models are saved for Day 5.

By the end of this lab you will be able to

  • Design, compile and train an MLP with early stopping and dropout; compare against logistic regression
  • Build a CNN with convolution, pooling and data augmentation; beat a dense-only baseline on images; read a confusion matrix
  • Turn a time series into supervised sequences with known-in-advance calendar features; train an LSTM; compare with baselines
  • Judge when deep learning is worth its complexity

1Part A · Prepare the credit matrices and benchmark 6 min

Why this matters

Neural networks need dense, scaled float32 arrays — exactly what the L1.2 preprocessor produces. The benchmark to beat is the L3.1 logistic model’s validation AUC.

Your tasks

  1. Load the L1.2 artefacts. Transform train/valid/test to float32 arrays.
  2. Load credit_policy.json and recompute the logistic validation AUC with credit_model.joblib.
Checkpoint — you should see

(207705, 46); benchmark AUC ≈ 0.829.

2Part A · MLP challenger with dropout and early stopping 14 min

Why this matters

An MLP can learn feature interactions automatically. Dropout randomly silences neurons during training (regularisation); EarlyStopping watches validation AUC and restores the best epoch. We do not use class weights so that outputs stay calibrated PDs.

Your tasks

  1. Build Sequential: Input → Dense(64, relu) → Dropout(0.2) → Dense(32, relu) → Dropout(0.2) → Dense(1, sigmoid).
  2. Compile with Adam(1e-3), binary cross-entropy, AUC metric. Fit ≤ 25 epochs, batch 1024, EarlyStopping(monitor='val_auc', mode='max', patience=3, restore_best_weights=True).
  3. Plot learning curves; report validation AUC, PR-AUC and the gap to the benchmark.
Checkpoint — you should see

Training stops after ≈ 10–20 epochs. MLP AUC ≈ 0.828 vs logistic 0.829 — a tie, with ≈ 5,000 parameters instead of 46.

Think like a practitioner

The MLP matches but does not beat logistic regression, has ~5,000 parameters instead of ~46 and no odds ratios. Which would you put in front of a regulator? What would change your mind?

3Part B · Load images and build a dense-only baseline 10 min

Why this matters

To prove convolution helps, first train a network that ignores spatial structure: flatten the 64×64 pixels into 4,096 numbers and use Dense layers. Images are scaled to [0, 1] and split stratified 70/15/15.

Your tasks

  1. Load kyc_documents_64.npz; scale to float32 in [0,1]; add a channel axis → (N, 64, 64, 1).
  2. Stratified split into Xi_tr/Xi_va/Xi_te. Show one example per class.
  3. Train a dense baseline: Flatten → Dense(128, relu) → Dense(5, softmax), sparse categorical cross-entropy, 8 epochs. Record test accuracy.
Checkpoint — you should see

(10500, 64, 64, 1) train images. The dense baseline reaches only ≈ 65–70% test accuracy with ≈ 525k parameters — documents appear at different positions, scales and angles, and a dense layer must re-learn each position separately.

4Part B · CNN with augmentation 16 min

Why this matters

Convolutions share small filters across the image — far fewer parameters, and translation-invariant features (a seal is a seal anywhere on the page). Pooling shrinks feature maps; GlobalAveragePooling replaces a huge flatten layer; augmentation (small rotations/shifts) mimics real scanning variation.

Your tasks

  1. Build: augmentation (RandomRotation 0.03, RandomTranslation 0.05) → Conv2D(16,3,relu,same) → MaxPool → Conv2D(32) → MaxPool → Conv2D(64) → GlobalAveragePooling → Dense(64) → Dropout(0.3) → Dense(5, softmax).
  2. Train ≤ 25 epochs (batch 64) with EarlyStopping on val_accuracy (patience 5).
  3. Report test accuracy and parameter count vs the dense model; plot the normalised confusion matrix and 6 misclassified images.
Checkpoint — you should see

CNN test accuracy ≈ 96–98% with ≈ 28k parameters (≈ 19× fewer than the dense model) — convolution + pooling give translation-tolerant features. Remaining errors are small, smudged or heavily rotated scans, often statement ↔ invoice (both tabular).

Think like a practitioner

For production routing you would not auto-route every document. How would you use the softmax confidence to send uncertain cases to a human?

5Part C · Sequences for next-day cash with known-in-advance features 12 min

Why this matters

An LSTM reads a window of past days. To be fair to SARIMAX (which knew the calendar), each timestep carries that day’s log withdrawal plus the next day’s calendar flags — the information Cash Ops genuinely has the evening before. We standardise with training statistics only.

Your tasks

  1. Load atm_network_daily.parquet from 2022-01-01. Build a feature matrix: standardised log withdrawal + next-day payday/pre-Eid/holiday/weekend/Ramadan flags.
  2. Create windows of 28 days → target = next day’s standardised log withdrawal. Split by target date: test from 2025-07-03 (as in L2.2).
  3. Compute two baselines on the test days: seasonal naive (same weekday last week) and Ridge on the flattened windows.
Checkpoint — you should see

Tensor ≈ (1372, 28, 6); 121 test days. Seasonal naive WAPE ≈ 12% (it ignores the calendar); Ridge on windows with next-day flags ≈ 1.3%.

💡 Hint

Index [:, -7, 0] picks the log withdrawal 7 timesteps before the end of each window — one week before the target day.

6Part C · Train the LSTM and compare 14 min

Why this matters

The LSTM’s gates learn what to remember across the 28 days. With only ~1,250 training sequences it can over-fit, so we hold out the last 10% of training windows (chronologically) for early stopping.

Your tasks

  1. Build Sequential: Input(28, 6) → LSTM(32) → Dense(16, relu) → Dense(1). Compile Adam(3e-3), MSE.
  2. Fit ≤ 60 epochs, batch 32, validation_split=0.1 (Keras takes the last 10% — chronological), EarlyStopping(patience=8, restore_best_weights=True).
  3. Report test WAPE; plot actual vs LSTM vs Ridge for the test period; save all three models and dl_results.json.
Checkpoint — you should see

LSTM WAPE ≈ 1.4–2% — far better than seasonal naive, but not better than the Ridge window model (≈ 1.3%). With ~1,250 sequences and strong calendar features, the linear model is hard to beat.

Think like a practitioner

Summarise Day 4 in one table: where did deep learning win decisively (images), tie (tabular credit, short time series)? Why does that pattern hold across the industry?

Stretch challenges

  1. Replace the LSTM with a 1-D CNN (Conv1D) or a GRU. Which trains fastest for the same accuracy?
  2. Extend Part C to 7-day-ahead (direct) forecasting by shifting the target and calendar by 7 — compare with L2.2’s results.
  3. Add Monte-Carlo dropout to the CNN (keep dropout on at inference, average 20 passes) to obtain an uncertainty score per document.

Troubleshooting

  • TensorFlow not installed / Python 3.13+ → use Python 3.10–3.12 (py -3.12 -m venv .venv) or Google Colab.
  • Results differ slightly from the reference → GPU/CPU and thread non-determinism; differences of ±0.5% are expected.
  • CNN slow on CPU → reduce epochs to 6 or batch 64; each epoch is ≈ 10–20 s on a laptop.
