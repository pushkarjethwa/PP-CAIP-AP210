Objective & scenario alignment

Horizon Gulf Bank (HGB) is a fictional UAE retail bank with 250,000 customers. Its Board approved Project MIZAN — an AI decisioning platform covering credit, fraud, collateral valuation, cash logistics, customer retention and document automation. You are a junior ML practitioner in the MIZAN squad.

A vendor claims their SVM fraud engine beats HGB’s random forest. You will run a fair bake-off on HGB’s own features and time budget. Separately, the IFRS 9 team needs a loss-severity model for loans that do default — a regression problem where SVR is a candidate.

Progressive architecture: reuses L3.3’s feature table and benchmark, and L1.2’s loan features.

By the end of this lab you will be able to

  • Build a correctly scaled SVM pipeline and tune C/γ with cross-validation on a stratified sample
  • Measure training/scoring time as a first-class metric
  • Scale non-linear SVMs with Nystroem kernel approximation + a linear SVM
  • Compare SVM variants with the RF benchmark at the fraud alert budget
  • Fit and tune SVR (C, ε, γ) for loss severity and compare with linear regression
AIP-210 exam link

AIP-210 SVM: kernel concept, C and gamma, SVC vs SVR, scaling, practical considerations (complexity, probability outputs).

1Load L3.3 features and define the evaluation 6 min

Why this matters

A bake-off is only fair if every model sees the same features, the same split and the same metric. We reuse L3.3’s table and its at_budget metric, and record the RF benchmark.

Your tasks

  1. Load card_features.parquet and fraud_metrics.json; split into tr/va/te.
  2. Re-create at_budget(y, score, amount) — it must work with any score (SVM decision values are not probabilities).
Checkpoint — you should see

1.5M rows; RF benchmark PR-AUC ≈ 0.94, recall@0.5% ≈ 0.89.

2Preprocessing for SVMs and a LinearSVC baseline 10 min

Why this matters

SVMs need numeric, scaled, complete inputs: impute, one-hot the two categorical columns (an ordinal code would impose a fake distance) and standardise. A LinearSVC on the undersampled training set is the cheap baseline.

Your tasks

  1. Build svm_prep: numeric → impute −1 → StandardScaler; categorical → OneHotEncoder.
  2. Create tr_u = all training fraud + 30k legit.
  3. Fit LinearSVC(C=0.1, class_weight='balanced'); time it; evaluate decision_function on validation with at_budget.
Checkpoint — you should see

Fits in well under a second; recall@0.5% ≈ 0.88, PR-AUC ≈ 0.93 — already competitive because the engineered features are strong.

3Tune an RBF SVM with cross-validation on a stratified sample 14 min

Why this matters

An RBF SVM can model interactions a linear SVM cannot — but only with the right C and γ. Grid-searching on all 34k rows would take too long, so we tune on a stratified 6k sample with 3-fold CV and PR-AUC scoring, then refit the winner on the full undersampled set.

Your tasks

  1. Draw a 6k stratified sample of tr_u.
  2. GridSearchCV over C ∈ {0.3, 1, 3, 10} and γ ∈ {0.01, 0.03, 0.1, 0.3}, scoring='average_precision', cv=3, n_jobs=-1. Show the results as a C × γ heat-map table.
  3. Refit SVC(kernel='rbf') with the best parameters on all of tr_u; time fit and validation scoring; add to board.
Checkpoint — you should see

Small γ (0.01–0.03) wins; large γ over-fits. The tuned RBF SVM edges past LinearSVC (PR-AUC ≈ 0.94 vs 0.93). Training is quick at 34k rows (≈ 1 s, ≈ 1,000 support vectors) but scoring 255k transactions takes ≈ 10–15 s — 100× slower than LinearSVC.

💡 Hint

Parameter names inside a Pipeline use the step name: svm__C, svm__gamma.

Think like a practitioner

Scoring time grows with the number of support vectors. Why is that a production problem for an authorisation system with a 50 ms SLA?

4Kernel approximation: RBF-like power at linear cost 12 min

Why this matters

Nyström samples landmark points and builds an explicit feature map that approximates the RBF kernel. A linear SVM on those features behaves like a kernel SVM but trains in roughly linear time — so we can use all training fraud and many more legitimate rows.

Your tasks

  1. Build Pipeline(svm_prep, Nystroem(kernel='rbf', gamma=best γ, n_components=600), LinearSVC(C=0.5, class_weight='balanced')).
  2. Train on all training fraud + 250k legit (tr_big); time it; evaluate.
  3. Add a final row with the RF benchmark from fm and compare.
Checkpoint — you should see

Nyström trains on 254k rows in ≈ 15 s with PR-AUC ≈ 0.94 — RBF-like accuracy on 7× more data. All four models sit within ≈ 0.015 PR-AUC of the random forest, which remains (narrowly) the best.

Think like a practitioner

Write the two-line verdict for the vendor meeting: accuracy, speed, explainability.

5SVR for loss severity on defaulted loans 16 min

Why this matters

IFRS 9 expected loss = PD × LGD × EAD. Given a default, how much will we lose? This is regression on the ~20k defaulted loans. SVR with an RBF kernel can capture non-linear effects; ε defines the error we are willing to ignore. We predict log loss and compare with linear regression.

Your tasks

  1. Load loan_features.parquet; keep defaulted loans (default_12m == 1); target log_loss = log1p(loss_amount_aed).
  2. Features: log loan amount, product, tenure, interest rate, log salary, DBR, bureau score. Build a scaled pipeline.
  3. Fit a LinearRegression baseline and tune SVR(kernel='rbf') over C ∈ {1, 10}, ε ∈ {0.05, 0.2}, γ ∈ {'scale', 0.05} on a 6k train sample (3-fold CV).
  4. Report MAE in AED and MAPE on the out-of-time defaults (split == 'test').
Checkpoint — you should see

≈ 22k defaults; both models land at ≈ 45% MAPE and ≈ AED 16k MAE — loss severity is mostly noise (recovery outcomes are random given what we know at origination). SVR adds nothing over the linear model.

Think like a practitioner

When the best model only reaches ~30% MAPE, what is the right way to use it in IFRS 9? (segment-level LGD averages, not loan-level point estimates)

Stretch challenges

  1. SVC(probability=True) uses Platt scaling with internal 5-fold CV. Measure its extra training time — and calibrate LinearSVC instead with CalibratedClassifierCV.
  2. Try SGDClassifier(loss='hinge') with Nyström features using partial_fit in chunks over all 1M training rows.

Troubleshooting

  • RBF fit takes > 3 min → reduce tr_u legit sample to 15k; complexity is super-linear.
  • LinearSVC ConvergenceWarning → increase max_iter=5000 or reduce C.
  • display undefined → run inside Jupyter.
