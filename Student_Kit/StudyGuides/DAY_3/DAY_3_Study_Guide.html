1. Logistic Regression, Probabilities and Decision Thresholds

What & Why

Despite the name, logistic regression is a classifier. It computes a linear score and passes it through the sigmoid function to produce a probability between 0 and 1 of the positive class. A decision threshold (default 0.5) turns that probability into a label. The threshold is a business choice, not a law: lowering it catches more positives (higher recall) at the cost of more false alarms (lower precision).

Coefficients are log-odds: a positive coefficient raises the probability of the positive class. This transparency is why logistic regression is a workhorse in credit scoring.

AnalogyA smoke alarm with a sensitivity dial: turn it up and it catches every fire but also burns toast alarms; turn it down and it stays quiet but may miss a real fire.
Finance example

A fraud model outputs 0.18 for a card payment. At threshold 0.5 it is approved; if the fraud team lowers the threshold to 0.10 for high-value transactions, the same payment is sent for step-up authentication.

Fit logistic regression and move the threshold
import pandas as pd
from sklearn.model_selection import train_test_split

tx = pd.read_csv("data/card_transactions.csv.gz")          # pandas reads .gz directly
feats = ["amount_aed", "merchant_risk_score", "distance_from_home_km",
         "customer_age", "card_tenure_months", "customer_monthly_salary_aed"]
X = tx[feats].fillna(tx[feats].median())
y = tx["is_fraud"]
# Large file: sample for teaching speed (keep stratification so fraud rows survive)
X, _, y, _ = train_test_split(X, y, train_size=200_000, stratify=y, random_state=42)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

clf = make_pipeline(StandardScaler(), LogisticRegression(class_weight="balanced", max_iter=1000))
clf.fit(X_tr, y_tr)

proba = clf.predict_proba(X_te)[:, 1]          # probability of the positive class (fraud)
for t in (0.3, 0.5, 0.8):
    flagged = (proba >= t).sum()
    print(f"threshold {t}: {flagged} transactions flagged")

2. k-Nearest Neighbours, Feature Scaling and Multi-class Classification

What & Why

kNN classifies a point by the majority class among its k closest training points (usually Euclidean distance). There is no training step; it stores the data (a "lazy learner") and does the work at prediction time. Small k = flexible and noisy (overfit); large k = smooth (underfit). Because it uses distance, feature scaling is essential.

Multi-class problems have more than two classes (for example risk grade A to E). Models either handle it natively (kNN, trees, logistic regression via softmax) or via one-vs-rest / one-vs-one strategies. Evaluate with per-class precision/recall and macro or weighted averages.

AnalogyAsking your five closest neighbours which restaurant they recommend and going with the majority, but first making sure "closest" is measured fairly (a distance in metres, not mixed with a rating out of 5).
Finance example

Classifying a loan application into a risk grade by looking at the most similar past applications. Without scaling, AED loan amounts (tens of thousands) would swamp the AECB score (hundreds) in the distance calculation.

kNN needs scaling: compare AUC with and without (loan defaults)
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import roc_auc_score

loans = pd.read_csv("data/loan_applications.csv")
f = ["loan_amount_aed", "monthly_salary_aed", "aecb_score", "debt_burden_ratio", "num_bureau_inquiries_6m"]
X, y = loans[f].fillna(loans[f].median()), loans["default_12m"]
X, _, y, _ = train_test_split(X, y, train_size=30_000, stratify=y, random_state=42)   # speed
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

raw = KNeighborsClassifier(n_neighbors=25).fit(X_tr, y_tr)
scaled = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=25)).fit(X_tr, y_tr)
print("AUC unscaled:", roc_auc_score(y_te, raw.predict_proba(X_te)[:, 1]))     # about 0.54 when run
print("AUC scaled  :", roc_auc_score(y_te, scaled.predict_proba(X_te)[:, 1]))  # about 0.74 when run

3. Classification Metrics: Confusion Matrix, Precision, Recall, F1, ROC and AUC

What & Why

Accuracy alone misleads when classes are imbalanced. Start from the confusion matrix:

Predicted positivePredicted negative
Actually positiveTrue Positive (TP)False Negative (FN): missed fraud
Actually negativeFalse Positive (FP): false alarmTrue Negative (TN)
  • Accuracy = (TP+TN) / all.
  • Precision = TP / (TP+FP): of the alerts raised, how many were real?
  • Recall (sensitivity) = TP / (TP+FN): of the real cases, how many did we catch?
  • F1 = harmonic mean of precision and recall.
  • ROC curve: true-positive rate vs false-positive rate across all thresholds; AUC is the area under it (0.5 = random, 1.0 = perfect), and is threshold-independent.
  • Precision-Recall AUC (average precision) is more informative than ROC AUC when positives are very rare.
AnalogyA fisherman's net: precision is "how much of what I pulled up is actually fish", recall is "how much of the fish in the lake did I catch".
Finance example

If only 0.1% of transactions are fraud, a model that always says "not fraud" is 99.9% accurate and catches nothing. Fraud teams track recall (money saved) and precision (customer friction and analyst workload) together.

Evaluate beyond accuracy
import pandas as pd
from sklearn.model_selection import train_test_split

tx = pd.read_csv("data/card_transactions.csv.gz")          # pandas reads .gz directly
feats = ["amount_aed", "merchant_risk_score", "distance_from_home_km",
         "customer_age", "card_tenure_months", "customer_monthly_salary_aed"]
X = tx[feats].fillna(tx[feats].median())
y = tx["is_fraud"]
# Large file: sample for teaching speed (keep stratification so fraud rows survive)
X, _, y, _ = train_test_split(X, y, train_size=200_000, stratify=y, random_state=42)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import (confusion_matrix, classification_report,
                             roc_auc_score, average_precision_score)

clf = make_pipeline(StandardScaler(), LogisticRegression(class_weight="balanced", max_iter=1000)).fit(X_tr, y_tr)
pred = clf.predict(X_te)
proba = clf.predict_proba(X_te)[:, 1]

print(confusion_matrix(y_te, pred))                  # rows = actual, columns = predicted
print(classification_report(y_te, pred, digits=3))
print("ROC AUC:", roc_auc_score(y_te, proba))
print("PR  AUC:", average_precision_score(y_te, proba))   # prefer this when fraud is rare

4. Class Imbalance and Tuning Classifiers

What & Why

When one class is rare, models drift toward the majority class. Options (try in this order): choose the right metric (PR-AUC, recall at a precision target), use stratified splits, apply class weights (class_weight="balanced"), tune the decision threshold, and only then consider resampling (over-sampling the minority or under-sampling the majority). Resample only the training data, never the test set. Libraries such as imbalanced-learn (SMOTE) are third-party add-ons to scikit-learn.

Tune with GridSearchCV or RandomizedSearchCV using a scoring metric that matches the business goal (for example "average_precision" or "f1"), not the default accuracy.

AnalogyTraining a lifeguard using footage where 999 of 1,000 swimmers are fine: unless you emphasise the rare drowning clips, they will learn to ignore them.
Finance example

The card fraud rate is a tiny fraction of volume. The tuned model is judged on how much fraud it catches at an acceptable alert volume, not on accuracy.

Tuning for the metric that matters (PR-AUC)
import pandas as pd
from sklearn.model_selection import train_test_split

tx = pd.read_csv("data/card_transactions.csv.gz")          # pandas reads .gz directly
feats = ["amount_aed", "merchant_risk_score", "distance_from_home_km",
         "customer_age", "card_tenure_months", "customer_monthly_salary_aed"]
X = tx[feats].fillna(tx[feats].median())
y = tx["is_fraud"]
# Large file: sample for teaching speed (keep stratification so fraud rows survive)
X, _, y, _ = train_test_split(X, y, train_size=200_000, stratify=y, random_state=42)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import GridSearchCV, StratifiedKFold

search = GridSearchCV(
    RandomForestClassifier(class_weight="balanced_subsample", random_state=42, n_jobs=-1),
    param_grid={"n_estimators": [100, 200], "max_depth": [6, 12], "min_samples_leaf": [5, 20]},
    cv=StratifiedKFold(n_splits=3, shuffle=True, random_state=42),
    scoring="average_precision")                     # PR-AUC, suited to rare positives
search.fit(X_tr, y_tr)
print(search.best_params_, round(search.best_score_, 4))

5. Clustering with k-Means

What & Why

Unsupervised learning finds structure without a target. k-Means partitions data into k groups: it places k centroids, assigns each point to the nearest one, moves each centroid to the mean of its points, and repeats until stable. You must choose k in advance and scale features first.

Choosing k: the elbow method (plot inertia, the within-cluster sum of squared distances, against k and look for the bend) and the silhouette score (from -1 to 1; higher means tighter, better-separated clusters). Always check that clusters are interpretable and actionable for the business, not just statistically neat.

AnalogySorting a pile of unlabelled photos into piles that look alike, then naming each pile afterwards ("beach", "city", "family").
Finance example

Marketing segments customers by balance, spend, digital logins and tenure into groups such as "digital-first spenders" or "dormant savers", each getting a different offer.

Segment customers and choose k
import pandas as pd
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score
from sklearn.preprocessing import StandardScaler

df = pd.read_csv("data/customers_raw.csv")
cols = ["avg_balance_aed", "card_spend_monthly_aed", "digital_logins_30d", "tenure_months", "num_products"]
Z = StandardScaler().fit_transform(df[cols].fillna(df[cols].median()))     # scale before clustering

for k in range(2, 8):
    km = KMeans(n_clusters=k, n_init="auto", random_state=42).fit(Z)
    sil = silhouette_score(Z, km.labels_, sample_size=10_000, random_state=42)
    print(f"k={k}  inertia={km.inertia_:,.0f}  silhouette={sil:.3f}")

best = KMeans(n_clusters=4, n_init="auto", random_state=42).fit(Z)
df["segment"] = best.labels_
print(df.groupby("segment")[cols].mean().round(1))          # profile each cluster

6. Hierarchical Clustering and Dendrograms

What & Why

Agglomerative hierarchical clustering starts with every point as its own cluster and repeatedly merges the two closest clusters until one remains. The merge history is drawn as a dendrogram: the height of a join shows how far apart the merged clusters were. Cutting the dendrogram at a chosen height gives a number of clusters. The linkage rule defines "closest" (ward, complete, average, single). Unlike k-Means you do not need to pick k up front, but it does not scale well to very large data.

AnalogyA family tree built from the bottom: first siblings join, then cousins, then whole branches, until everyone is under one ancestor.
Finance example

Grouping a few hundred branches by their transaction profile so that similar branches can share staffing and cash-handling policies; the dendrogram shows which branches are near-twins.

Dendrogram on a sample (hierarchical clustering is memory-hungry)
import matplotlib.pyplot as plt
from scipy.cluster.hierarchy import linkage, dendrogram
from sklearn.cluster import AgglomerativeClustering

plt.figure(figsize=(10, 4))
dendrogram(linkage(sample, method="ward"), no_labels=True)
plt.title("Customer dendrogram (ward linkage)"); plt.ylabel("Merge distance"); plt.show()

labels = AgglomerativeClustering(n_clusters=4, linkage="ward").fit_predict(sample)

7. Decision Trees and Random Forests

What & Why

A decision tree asks a sequence of yes/no questions. The root is the first split, nodes are decisions, branches are answers and leaves are final predictions. At each node the algorithm picks the feature and threshold that best reduces impurity:

  • Gini = 1 - sum(p_i²) (0 = pure node).
  • Entropy = - sum(p_i * log2 p_i) (0 = pure node); the drop in entropy is the information gain.

Unrestricted trees overfit. Control with max_depth, min_samples_leaf and cost-complexity pruning (ccp_alpha). Trees also do regression (DecisionTreeRegressor); leaves predict the average target. They need no feature scaling and are easy to explain.

A random forest averages many trees, each trained on a bootstrap sample of the rows and a random subset of features at each split (bagging + feature randomness). Combining many decorrelated trees lowers variance and overfitting. feature_importances_ gives impurity-based importance, which can be biased toward high-cardinality or continuous features; permutation_importance on held-out data is a more reliable cross-check.

AnalogyOne expert's checklist can be quirky; ask a hundred experts who each saw slightly different cases and let them vote, and the quirks cancel out.
Finance example

A single tree gives credit officers a readable rule path ("AECB score < 650 and debt burden > 0.5 leads to high risk"). A random forest usually predicts more accurately but is harder to explain, so teams often pair it with importance reports.

A pruned tree you can print, then a random forest with importances

from sklearn.model_selection import train_test_split

tx = pd.read_csv("data/card_transactions.csv.gz")          # pandas reads .gz directly
feats = ["amount_aed", "merchant_risk_score", "distance_from_home_km",
         "customer_age", "card_tenure_months", "customer_monthly_salary_aed"]
X = tx[feats].fillna(tx[feats].median())
y = tx["is_fraud"]
# Large file: sample for teaching speed (keep stratification so fraud rows survive)
X, _, y, _ = train_test_split(X, y, train_size=200_000, stratify=y, random_state=42)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

from sklearn.tree import DecisionTreeClassifier, export_text
from sklearn.ensemble import RandomForestClassifier
from sklearn.inspection import permutation_importance
from sklearn.metrics import average_precision_score
import pandas as pd

tree = DecisionTreeClassifier(max_depth=4, min_samples_leaf=50, class_weight="balanced", random_state=42).fit(X_tr, y_tr)
print(export_text(tree, feature_names=list(X_tr.columns)))          # human-readable rules

rf = RandomForestClassifier(n_estimators=200, min_samples_leaf=5, class_weight="balanced_subsample",
                            n_jobs=-1, random_state=42).fit(X_tr, y_tr)
print("RF PR-AUC:", average_precision_score(y_te, rf.predict_proba(X_te)[:, 1]))

imp = pd.Series(rf.feature_importances_, index=X_tr.columns).sort_values(ascending=False)
print(imp)                                                          # impurity-based (can be biased)

# More reliable cross-check on held-out data (use a subsample for speed)
idx = X_te.sample(5000, random_state=1).index
perm = permutation_importance(rf, X_te.loc[idx], y_te.loc[idx], scoring="average_precision",
                              n_repeats=5, random_state=42, n_jobs=-1)
print(pd.Series(perm.importances_mean, index=X_te.columns).sort_values(ascending=False))

Common Pitfalls & Anti-Patterns

⚠ Reporting accuracy on imbalanced fraud data

"Predict never fraud" scores 99.9% and catches nothing. Report recall, precision and PR-AUC.

⚠ Using the default 0.5 threshold blindly

The right cut-off depends on the cost of a missed fraud versus a blocked customer. Choose it with the business.

⚠ Clustering unscaled data

k-Means and kNN are distance-based; the largest-unit feature dominates. Standardise first.

⚠ Oversampling before the split

Duplicated minority rows then appear in both train and test, inflating results. Resample only inside training folds.

⚠ Trusting impurity importances as causes

They show what the model used, not what causes fraud, and can favour high-cardinality features. Cross-check with permutation importance.

⚠ Letting a deep tree run free

An unpruned tree memorises the training set. Limit depth, leaf size or use ccp_alpha.

Interactive Knowledge Check

Answer in your head (or out loud with a colleague) first, then reveal.

1. Fraud is 0.1% of transactions. A model has 99.9% accuracy. Is it good?

Not necessarily: always predicting "not fraud" gives the same accuracy. Check recall, precision, PR-AUC and the confusion matrix.

2. You lower the fraud threshold from 0.5 to 0.2. What happens to recall and precision?

Recall usually rises (more fraud caught) and precision usually falls (more false alarms).

3. Why is scaling required for kNN but not for a decision tree?

kNN relies on distances, so large-unit features dominate. Trees split on one feature at a time, so scale does not matter.

4. What does an AUC of 0.5 mean?

The model ranks positives and negatives no better than random chance.

5. How does a random forest reduce overfitting compared with one deep tree?

It averages many trees trained on bootstrap samples and random feature subsets, which decorrelates them and lowers variance.
