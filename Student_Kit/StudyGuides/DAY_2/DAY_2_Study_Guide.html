1. Train / Validation / Test Splits and Generalisation

What & Why

A model must be judged on data it has never seen, because the goal is generalisation: good performance on tomorrow's data, not memorised history.

  • Training set: the model learns its parameters here.
  • Validation set: used to compare models and tune hyperparameters.
  • Test set: touched once at the end for an honest final estimate. If you tune against it repeatedly it stops being a fair test.

Common split: 60/20/20 or 70/15/15. For classification use stratify=y so each split keeps the class ratio. For time-ordered data split chronologically, never randomly.

AnalogyTraining is studying with practice papers, validation is the mock exam you use to adjust your study plan, and the test is the real exam you sit once.
Finance example

A mortgage valuation model is built from 2018-2025 valuations. The bank only cares how it values new properties next quarter, so a held-out test set stands in for those future cases.

A 60/20/20 split for the property-valuation data
import pandas as pd
from sklearn.model_selection import train_test_split

df = pd.read_csv("data/property_valuations.csv")
num = ["bedrooms", "size_sqft", "building_age_years", "floor", "parking_spaces",
       "distance_to_metro_km", "service_charge_aed_sqft", "private_pool", "furnished", "off_plan"]
X, y = df[num].fillna(df[num].median()), df["valuation_aed"]

# 1) carve off the final test set (20%)
X_tmp, X_test, y_tmp, y_test = train_test_split(X, y, test_size=0.20, random_state=42)
# 2) split the remainder into train / validation (0.25 of 80% = 20% overall)
X_train, X_val, y_train, y_val = train_test_split(X_tmp, y_tmp, test_size=0.25, random_state=42)

print(len(X_train), len(X_val), len(X_test))

2. Underfitting, Overfitting and the Bias-Variance Trade-off

What & Why
  • Underfitting (high bias): the model is too simple and performs poorly on both training and validation data.
  • Overfitting (high variance): the model memorises noise; training error is tiny but validation error is much larger.
  • Good fit: training and validation errors are both low and close together.

Diagnose with the gap between training and validation scores, and with learning or validation curves. Remedies for overfitting: more data, simpler model, regularisation, early stopping, fewer features. For underfitting: richer features or a more flexible model.

AnalogyUnderfit: a student who only learned "everything is average". Overfit: a student who memorised last year's exact questions and freezes on new ones.
Finance example

An over-deep decision tree values every training flat almost perfectly yet misprices new ones. Plotting error against tree depth shows the validation error bottoming out and then rising.

Training vs validation RMSE as tree depth grows
import numpy as np
from sklearn.tree import DecisionTreeRegressor
from sklearn.metrics import mean_squared_error

def rmse(y_true, y_pred):
    return float(np.sqrt(mean_squared_error(y_true, y_pred)))

for depth in [1, 3, 5, 8, 12, 20]:
    m = DecisionTreeRegressor(max_depth=depth, random_state=42).fit(X_train, y_train)
    print(f"depth={depth:>2}  train RMSE={rmse(y_train, m.predict(X_train)):>10,.0f}"
          f"  val RMSE={rmse(y_val, m.predict(X_val)):>10,.0f}")
# Pick the depth where validation RMSE is lowest, not training RMSE.

3. Cross-Validation, Parameters vs Hyperparameters, Tuning and Baselines

What & Why

Parameters are learned from data (regression coefficients, neural-network weights). Hyperparameters are set by you before training (tree depth, Ridge alpha, k in kNN, learning rate) and are tuned.

k-fold cross-validation splits the training data into k folds, trains on k-1 and validates on the remaining fold, rotating k times and averaging the scores. It gives a more stable estimate than a single split. GridSearchCV automates "try each hyperparameter combination with cross-validation". For time series use TimeSeriesSplit so the validation fold is always after the training fold.

Always compare against a baseline: a trivial predictor (for example the training mean, or "same as last week"). A model that cannot beat the baseline adds no value.

AnalogyCross-validation is taking five different mock exams instead of one, so a lucky or unlucky paper does not decide your grade. A baseline is the score you get by guessing the class average.
Finance example

The AVM team tunes the maximum depth of a tree model with 5-fold cross-validation, and reports its error next to "always predict the average valuation" so management can see the improvement is real.

Baseline, cross-validation and a small grid search
from sklearn.dummy import DummyRegressor
from sklearn.ensemble import RandomForestRegressor
from sklearn.model_selection import cross_val_score, GridSearchCV, KFold

cv = KFold(n_splits=5, shuffle=True, random_state=42)

base = cross_val_score(DummyRegressor(strategy="mean"), X_train, y_train,
                       cv=cv, scoring="neg_root_mean_squared_error")
print("Baseline RMSE:", -base.mean())

grid = GridSearchCV(
    RandomForestRegressor(random_state=42, n_jobs=-1),
    param_grid={"n_estimators": [100, 200], "max_depth": [6, 12, None]},   # hyperparameters
    cv=cv, scoring="neg_root_mean_squared_error")
grid.fit(X_train, y_train)

print("Best params:", grid.best_params_)
print("CV RMSE    :", -grid.best_score_)
# Only now evaluate once on the untouched test set: grid.score / predict on X_test

4. Linear Regression, Coefficients, Residuals and Error Metrics

What & Why

Simple linear regression fits y = b0 + b1*x; multiple linear regression uses several features: y = b0 + b1*x1 + b2*x2 + .... The intercept (b0) is the prediction when all features are zero; each coefficient is the expected change in y for a one-unit rise in that feature, holding the others constant. A residual is actual - predicted.

Fitting minimises the sum of squared residuals (ordinary least squares). Evaluation metrics:

AnalogyDrawing the best straight "trend line" through a cloud of dots; the residuals are the vertical distances from each dot to the line.
Finance example

Each extra square foot adds roughly a fixed number of AED to a valuation, holding other factors fixed. That coefficient is directly explainable to a credit committee, which is why linear models remain popular in banking.

MetricFormulaNotes
MAEmean(|y - y_hat|)Average error in AED; robust to outliers; easy to explain.
MSEmean((y - y_hat)^2)Penalises large errors heavily; units are AED squared.
RMSEsqrt(MSE)Back in AED; most commonly reported.
R²1 - SS_res / SS_totShare of variance explained; can be negative on test data if the model is worse than predicting the mean.
Fit, inspect coefficients, evaluate
import numpy as np, pandas as pd
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score

lr = LinearRegression().fit(X_train, y_train)

print("intercept:", round(lr.intercept_, 1))
print(pd.Series(lr.coef_, index=X_train.columns).round(1).sort_values())

pred = lr.predict(X_val)
resid = y_val - pred                                  # actual - predicted
print("MAE :", mean_absolute_error(y_val, pred))
print("RMSE:", np.sqrt(mean_squared_error(y_val, pred)))
print("R2  :", r2_score(y_val, pred))

5. Regularised Regression (Ridge, Lasso) and Gradient Descent

What & Why

Regularisation adds a penalty on large coefficients to curb overfitting, especially with many or correlated features.

  • Ridge (L2): penalises the sum of squared coefficients; shrinks them toward zero but rarely to exactly zero; good with correlated features.
  • Lasso (L1): penalises the sum of absolute coefficients; can shrink some exactly to zero, acting as automatic feature selection.

In scikit-learn the strength is alpha (bigger = stronger shrinkage). Scale features first, otherwise the penalty treats features unfairly.

Gradient descent finds the best coefficients iteratively: compute the slope (gradient) of the loss, take a step downhill of size learning rate, repeat. Too large a rate overshoots; too small crawls.

AnalogyRidge/Lasso is a budget: the model may "spend" coefficient size only if it earns its keep. Gradient descent is walking down a foggy hill by always stepping in the steepest downhill direction you can feel.
Finance example

A valuation model with 40 correlated property attributes can wobble badly on new data. Ridge keeps coefficients stable; Lasso highlights which attributes the model genuinely relies on.

Ridge and Lasso inside a scaling pipeline
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import Ridge, Lasso

for name, reg in [("Ridge", Ridge(alpha=1.0)), ("Lasso", Lasso(alpha=100.0, max_iter=10000))]:
    pipe = make_pipeline(StandardScaler(), reg).fit(X_train, y_train)
    print(name, "val R2 =", round(pipe.score(X_val, y_val), 4))

# Which features did Lasso zero out? (Tune alpha with GridSearchCV in practice.)
lasso = make_pipeline(StandardScaler(), Lasso(alpha=100.0, max_iter=10000)).fit(X_train, y_train)
print(dict(zip(X_train.columns, lasso[-1].coef_.round(0))))
Gradient descent from scratch (NumPy) for y = w*x + b with MSE loss
import numpy as np

rng = np.random.default_rng(0)
x = rng.uniform(0, 10, 200)
y = 3.0 * x + 5.0 + rng.normal(0, 1, 200)       # true w=3, b=5

w, b, lr = 0.0, 0.0, 0.01
for epoch in range(2000):
    y_hat = w * x + b
    err = y_hat - y
    dw = (2 / len(x)) * np.sum(err * x)          # d(MSE)/dw
    db = (2 / len(x)) * np.sum(err)              # d(MSE)/db
    w -= lr * dw                                 # step downhill
    b -= lr * db
print(round(w, 2), round(b, 2))                  # close to 3 and 5

6. Time Series: Components, Lags, Forecasting and Leakage

What & Why

A time series is data ordered in time, where the past influences the future, so rows are not independent. Typical components: trend (long-term direction), seasonality (fixed-period repeats: weekly, monthly, yearly), cyclic behaviour (longer, irregular swings) and noise.

  • Lag features: yesterday's and last week's values as inputs (shift).
  • Moving average: a rolling mean that smooths noise.
  • Univariate forecasting uses only the series' own history; multivariate adds other drivers (holidays, paydays, weather).
  • Evaluation: split by time, compare with a naive baseline (for example "same day last week"), and report MAE/RMSE/MAPE.

Future-data leakage: a rolling mean that includes today's value, or random shuffling before splitting, lets the model peek at the future. Always shift(1) before rolling.

AnalogyPredicting tomorrow's traffic from the last few weeks of the same road (lags), and knowing that Fridays and school holidays behave differently (multivariate drivers).
Finance example

An ATM's cash demand spikes around paydays, Eid and public holidays and follows a weekly rhythm. Forecasting it lets the bank load the right cash amount: too little means an empty ATM, too much means idle cash and cost.

Lag features, a shifted rolling mean and a chronological split (ATM100)
import numpy as np, pandas as pd
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import mean_absolute_error

atm = pd.read_csv("data/atm_cash_daily.csv", parse_dates=["date"])
s = atm[atm["atm_id"] == "ATM100"].sort_values("date").set_index("date").copy()

# Lags and a rolling mean; shift(1) so today's value never feeds today's prediction
s["lag_1"] = s["withdrawal_aed"].shift(1)
s["lag_7"] = s["withdrawal_aed"].shift(7)
s["roll_7"] = s["withdrawal_aed"].shift(1).rolling(7).mean()
s = s.dropna()

drivers = ["is_ramadan", "is_public_holiday", "is_pre_eid_window", "is_payday_window", "is_weekend"]  # multivariate
feats = ["lag_1", "lag_7", "roll_7"] + drivers

cut = int(len(s) * 0.8)                          # chronological split, no shuffling
train, test = s.iloc[:cut], s.iloc[cut:]

naive_mae = mean_absolute_error(test["withdrawal_aed"], test["lag_7"])      # seasonal-naive baseline
model = RandomForestRegressor(n_estimators=200, random_state=42, n_jobs=-1).fit(train[feats], train["withdrawal_aed"])
model_mae = mean_absolute_error(test["withdrawal_aed"], model.predict(test[feats]))
print(f"naive MAE={naive_mae:,.0f}   model MAE={model_mae:,.0f}")
Optional: a classical univariate model with statsmodels (weekly seasonality)
from statsmodels.tsa.statespace.sarimax import SARIMAX

endog = train["withdrawal_aed"].asfreq("D")        # give the index an explicit daily frequency
fit = SARIMAX(endog, order=(1, 1, 1),
              seasonal_order=(1, 0, 1, 7)).fit(disp=False)        # seasonal period = 7 days
forecast = fit.forecast(steps=len(test))
# To go multivariate pass exog=train[drivers] and exog=test[drivers] when forecasting.

Common Pitfalls & Anti-Patterns

⚠ Tuning on the test set

Each peek at the test score makes it optimistic. Tune on validation or cross-validation; open the test set once.

⚠ Random splits on time series

Shuffling lets the model train on the future. Split chronologically and use TimeSeriesSplit.

⚠ Rolling statistics without shift

A 7-day mean that includes today leaks the answer. Use shift(1) first.

⚠ No baseline

An RMSE of AED 80,000 means nothing until compared with a naive predictor.

⚠ Unscaled features with Ridge/Lasso

The penalty depends on coefficient size, which depends on feature units. Standardise first.

⚠ Judging by R² alone

R² hides unit-level error. Report MAE/RMSE in AED and look at residuals by segment.

Interactive Knowledge Check

Answer in your head (or out loud with a colleague) first, then reveal.

1. Training RMSE is AED 5,000 but validation RMSE is AED 60,000. What is happening and what can you try?

Overfitting. Try a simpler model, regularisation, more data, fewer features or early stopping.

2. What is the difference between a parameter and a hyperparameter?

Parameters are learned from data (coefficients). Hyperparameters are set before training and tuned (alpha, max_depth, k).

3. Which regularisation can drive coefficients exactly to zero?

Lasso (L1), so it also performs feature selection. Ridge (L2) only shrinks them.

4. Why must a rolling average of ATM withdrawals be shifted by one day?

Otherwise today's actual value is inside the feature used to predict today: future-data leakage.

5. Your forecast model's MAE is no better than "same as last week". What now?

It adds no value over the seasonal-naive baseline. Improve features/drivers or use the simpler baseline.
